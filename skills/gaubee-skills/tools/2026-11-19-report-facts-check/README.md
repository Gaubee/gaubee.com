# report-facts-check — 日报里的数字逐项对账

## 是什么

把一份日报里的数字抽出来，跟权威源逐项比对：星标累计、星标新增、公开/私有提交数、媒体 gen、
补丁卷文件数、译文累计、图谱边数。「最新一天」硬判，「历史日期」的媒体类只提示（那记的是当时水位）。

## 解决什么

2026-11-19 写 2026-11-18 日报时，我把补丁卷文件数写成 87，实际是 55。这类错误人眼很难抓住，
但会连累整份报告的可信度。`report-lint` 只查星标累计，提交数有专门工具，媒体/译文/图谱一直没人核。

首跑还查出一个真错误：2026-11-16 的日报把改名来的 `gvisor/gvisor` 当成新增，真正的新增是
`goeist-font`。报告与已发布 event 都已修正。

## 一个必须记住的口径差异

「新增」按 **starred_at 落在该日** 统计，不能用 `changes[run-day]` 的 added 减改名。
2026-11-19 实证：`goeist-font` 的 starred_at 是 11-16，但出现在 `changes[11-16]` 里，
用差分算 11-16 的新增会漏掉它。改名不影响 starred_at，按 starred_at 统计天然排除改名。

## 怎么跑

```bash
bun tools/2026-11-19-report-facts-check/report-facts-check.ts 2026-11-18
bun tools/2026-11-19-report-facts-check/report-facts-check.ts 2026-11-18 --json
```

退出码：0 = 核心数字全对；1 = 有硬错误；2 = 参数/文件缺失。只读。

## 真实示例输出（2026-11-19）

```text
report-facts-check：2026-11-18（最新一天，硬判）
  ✓ 星标累计：写 1799，实际 1799
  ✓ 星标新增：写 3，实际 3（按 starred_at 落在该日统计）
  ✓ 媒体 gen：写 40，实际 40
  ✓ 译文累计：写 3266，实际 3266
  ✓ 图谱边数：写 5890，实际 5890

REPORT FACTS OK：核心数字与脚本口径一致
```

历史日期会看到这样的提示行（不是错误）：

```text
  △ 媒体 gen：写 38，实际 40（历史报表记的是当时水位）
```

## 判读建议

- 只报「写 N，实际 M」，不给修法：数字背后可能是口径错，也可能是抓取漏了，得人判断。
- `△` 不是失败。历史报表的数字就该是当时的值，改了反而失真。
- 它是发布前的最后一道：定稿后跑一次，红了先改数字再发。
