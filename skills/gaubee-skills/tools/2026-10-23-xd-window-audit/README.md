# xd-window-audit — X 日报归窗对账

## 是什么

对 `~/.gaubee-skills/data/sources/x-likes/changes/<R>.json` 里每条 added 点赞，统计它在 `src/content/events` 的 x-daily / x-archive 文件中「同窗日」（报告日 = R−1，方案 a）内的出现次数：恰 1 次 ✓、0 次 ✗ 缺窗、>1 次 ✗ 重复。任一异常 exit 1。

## 解决什么

2026-10-22 方案 a 上线时发生过三连渲染事故：同一份差分被 `--force` 渲染进三个日报，靠人工对账才发现并回滚。本工具把「每条捕捉恰好落一个窗」的不变量固化成一条命令，供日报发布前自检或事后抽查。

## 怎么跑

```bash
bun tools/2026-10-23-xd-window-audit/xd-window-audit.ts            # 全量 17 个 changes
bun tools/2026-10-23-xd-window-audit/xd-window-audit.ts --limit 7  # 只看最近 7 次抓取
```

## 判读（2026-10-23 人工核验）

- **全部 37 条异常都是 10-18 定窗前的历史代差，不是现行违规**：
  - 4 条「缺窗」实际在更早的周刊容器里（`01826.signals-weekly-W41.md`，grep 实证），日报管道尚未存在时的落点，非数据丢失；
  - 33 条「重复」是早期「日报+归档同窗双份」形态，涉及两份都是已发布卷，按「不删除历史快照与已发布卷」保留不动。
- **10-18 起的窗口（含 10-21 会话失效事故与 10-22 方案 a 三连渲染自纠后的重建）全部恰一窗**——现行 runbook 不变量成立，本工具以后作为日报发布前的例行自检。
