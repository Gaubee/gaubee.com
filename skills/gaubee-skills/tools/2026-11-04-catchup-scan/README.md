# catchup-scan — 补跑缺口扫描

## 是什么

给定日期区间，逐日核对四个源的 changes、两份日报的 reports 文件与站点 event，打印「哪天缺什么」。把「连续几天没跑、现在要补哪些」从手工盘点变成一条命令。

## 解决什么

2026-11-04 的补跑里，缺口是靠一条条 `ls` 拼出来的（stars 断在哪、commits 缺几天、哪几天没日报、周报月报漏了）。这个盘点每次都要重做，且容易漏。

关键语义区分（工具按此判硬软）：

- **commits** 按报告日命名且可按日回填 → 缺就是硬缺口
- **stars / deps / X** 是「累积差分」源，漏跑的中间日会把差额并进最近一次运行日 → 缺中间日属补跑常态，只提示不算缺口

## 怎么跑

```bash
bun tools/2026-11-04-catchup-scan/catchup-scan.ts                        # 自动区间
bun tools/2026-11-04-catchup-scan/catchup-scan.ts --from 2026-10-31 --to 2026-11-03
```

## 真实示例输出（2026-11-04 补跑验证，exit 0）

```text
补跑区间 2026-10-31 .. 2026-11-03（数据最晚 2026-11-04，考察口径：报告日 = T-1）
  2026-10-31  星标·  提交✓  依赖·  X·  GH日报✓  X日报·
  2026-11-01  星标·  提交✓  依赖·  X·  GH日报✓  X日报·
  2026-11-02  星标·  提交✓  依赖·  X·  GH日报✓  X日报·
  2026-11-03  星标✓  提交✓  依赖✓  X✓  GH日报✓  X日报✓

提示 12 项（非硬缺口，累积差分源的正常形态）
无硬缺口：commits 齐全，GitHub 日报齐全
```

补跑正是照这张表做的：commits 逐日回填、GitHub 日报逐日补、X 只做 11-03 一份（方案 a）。
