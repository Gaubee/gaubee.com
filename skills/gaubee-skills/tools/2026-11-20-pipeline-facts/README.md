# pipeline-facts — 写日报时要用到的管道数字，一次打全

## 是什么

日报的「管道」段要填补丁卷名、文件数、字节数、gen 代号、远端卷数、对象总数、译文累计、
图谱边数、X 抓取构成、staging 水位。这些数字散在 06:00 日志、manifest 文件、翻译库与
tech-graph 里。本工具一次读出来，按行文顺序排好，直接照抄。

## 解决什么

2026-11-19 写日报时，我把补丁卷文件数抄成了另一个卷的（87 vs 实际 55）。
这类错误靠人眼盯不住，之后才被 `report-facts-check` 抓出来。
现在写作前先跑本工具，数字只有一个来源。

顺带修了一个取数陷阱：卷名不在 06:00 的日志里（daily-auto 只截了日志尾部两行），
必须从 `manifest-<gen>.json` 的 volumes 里取最后一个 `patch-*`。

## 怎么跑

```bash
bun tools/2026-11-20-pipeline-facts/pipeline-facts.ts
bun tools/2026-11-20-pipeline-facts/pipeline-facts.ts --date 2026-11-19
```

退出码：0 = 已输出；2 = 数据缺失。只读。

## 真实示例输出（2026-11-20）

```text
pipeline-facts：报告日 2026-11-19（打包日 2026-11-20）

补丁卷：patch-2026-11-20.tar，55 个文件，35.84MB
媒体 gen：41（295 卷）
对象总数：9342
译文累计：3276
技能 Graph：212 项目 × 1524 技术 × 1805 星标，5911 条边
站点公开视图：129 项目 × 1015 技术 × 1805 星标，4174 条边
X 抓取：15 条（14 赞 / 1 帖）
staging：532 个文件 388.4MB
```

## 判读建议

- 它只给「当前水位」，不判断对错。写完日报再跑 `report-facts-check <date>` 复核。
- 补丁卷成员数用日志里的「N 新对象」，字节数也用日志值（含 tar 头开销，与卷内文件总大小略有差异）。
- `--date` 指的是**报告日**，打包日自动取次日；跨日补跑时注意这点。
