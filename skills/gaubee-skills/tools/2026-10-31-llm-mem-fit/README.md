# llm-mem-fit — 端侧 LLM 内存适配估算

## 是什么

「这个模型我的 16GB Mac 跑得动吗」的计算器：参数量 × 量化位宽估权重体积，加 KV cache 上界与运行时余量，对比可用内存给出三档判定（轻松 / 可跑 / 不可行）。纯计算，零网络零依赖。

## 解决什么

本周 LFM3-1.7B、uzu、Bun AOT 等端侧信号三连，profile 又写着「16GB 内存敏感」——每次看到一个模型都要心算一遍内存账。本工具把账算好并明确标注估算口径（KV cache 是传统 MHA 上界，GQA/线性注意力架构可低一个数量级，实际以引擎实测为准）。

## 怎么跑

```bash
bun tools/2026-10-31-llm-mem-fit/llm-mem-fit.ts 1.7 4 8       # 1.7B、4bit、8K 上下文
bun tools/2026-10-31-llm-mem-fit/llm-mem-fit.ts 7 8 32 --avail 12
```

## 真实示例输出（2026-10-31 首跑）

```text
模型 1.7B @ 4bit，上下文 8K，可用内存按 12GB 估：
  权重 0.79 GB + KV cache 1.00 GB + 运行时余量 0.8 GB = 总占用 2.59 GB
  判定：轻松：余量充足，可同时开其它大应用

模型 7B @ 8bit，上下文 32K，可用内存按 12GB 估：
  权重 6.52 GB + KV cache 4.00 GB + 运行时余量 0.8 GB = 总占用 11.32 GB
  判定：可跑：贴着可用内存，建议关掉大应用后独占运行
```

## 边界

- 首版 KV 公式量纲写错过（输出上万 GB 的荒谬值），已改为「128KB/token 上界 × ctx」并显式标注口径；对线性注意力类模型（LFM3 这类跑 100K 上下文的）上界会严重高估，结论偏保守即安全。
- `--avail` 默认 12GB（16GB 机器系统与其余应用后的典型值），可按场景调整。
