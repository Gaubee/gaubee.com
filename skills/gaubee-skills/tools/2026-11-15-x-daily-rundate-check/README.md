# x-daily-rundate-check — 补跑前先算清 run-date 配不配对

## 是什么

X 日报的归窗口径是「`--run-date` 的抓取差分归 run-date − 1」。补跑漏掉的日子时，run-date 会晚于「报告日 + 1」，一次差分覆盖好几天。本工具在**动手生成之前**回答两件事：

1. 这个报告日、这个 run-date，差分到底归不归它；
2. 按生成器的真实口径，预计能选出几条。

不写文件、不调生成器，纯预览。

## 解决什么

2026-11-14 补跑 11-12/11-13 时，旧生成器把同一份 18 条差分对两个报告日各算一遍，两份日报完全相同。
生成器已在 2026-11-15 修好（不配对时降级为只按时间窗选），但修好之后**结果可能只剩几条甚至 0 条**——
0 条会 fail-closed 退出。所以在按下回车前需要先知道预期，而不是生成完才发现文件是空的。

首跑就复现了当时的情况：11-12 因为 11-13 没抓过而没有配对差分，预计只剩 2 条（实际产出正是 2 条）。

## 估算口径必须与生成器一致

第一版把 posted 同时算进了「差分」和「时间窗」，11-13 估 21 条、实际产出 16 条。修正后按生成器真实口径：

- 差分只收 liked/bookmarked（posted 走时间窗，不按差分归属）；
- 时间窗收 posted/reposted 且 `created_at` 落在该本地日；
- 两者按 id 去重，重叠部分扣一次。

修正后四天全部精确对上：

| 报告日 | 预计 | 实际 |
| --- | --- | --- |
| 2026-11-11 | 16 | 16 |
| 2026-11-12 | 2 | 2 |
| 2026-11-13 | 16 | 16 |
| 2026-11-14 | 13 | 13 |

## 怎么跑

```bash
bun tools/2026-11-15-x-daily-rundate-check/x-daily-rundate-check.ts --date 2026-11-14
bun tools/2026-11-15-x-daily-rundate-check/x-daily-rundate-check.ts --from 2026-11-11 --to 2026-11-14
```

退出码：0 = 全部配对且预计非空；1 = 有不配对日或预计 0 条；2 = 参数/数据异常。

## 真实示例输出（2026-11-15）

```text
run-date 配对检查 2026-11-11 .. 2026-11-14（口径：run-date = 报告日 + 1）
  2026-11-11  次日 2026-11-12  配对　差分 15 条 + 时间窗 1 条 → 预计 16 条
  2026-11-12  次日 2026-11-13  不配对　该日无 2026-11-13 的差分，只按时间窗选 → 预计 2 条
  2026-11-13  次日 2026-11-14  配对　差分 13 条 + 时间窗 3 条 → 预计 16 条
  2026-11-14  次日 2026-11-15  配对　差分 13 条 + 时间窗 0 条 → 预计 13 条

需要注意 1 天：
  - 2026-11-12 没有 2026-11-13 的 changes（可用差分日期：2026-11-14）。补跑请直接对着最近的实际抓取日生成，或者先 fetch 再生成。
```

## 判读建议

- 「不配对」不代表不能生成，而是**那天的赞丢了**：差分在别的日子，那天只会有自己发的帖。要补回赞，得对着实际抓取日重新生成。
- 预计 0 条时不要硬跑，生成器会 fail-closed 退出，该日应当跳过日报。
- 它是补跑专用工具；日常 cron 的 run-date 恒为「今天」，报告日恒为「昨天」，天然配对，不需要每天跑。
