# commit-workflow-groups — 把一天的提交按「工作流候选」预先聚类

## 是什么

日报的提交段要求按工作流归组写人话，而不是罗列「N commits」。但分组一直靠人读消息手工做：
13 条还好，199 条的高活跃日就要花很久。本工具先把显而易见的归属算出来：

1. 同一仓库同一 conventional 前缀（`feat` / `fix` / `docs` / `chore` / `refactor` / `test`，带 scope 时保留）→ 一组；
2. 同仓库内共享词超过 30% 的组再并一次（Jaccard 相似度，中文按二字切、英文按单词）；
3. 输出「组 + 条数 + 代表消息 + 前几条明细」。

不做的事：不改写消息、不写报告、不判断跨仓库是否同一主线（那需要理解业务）。

## 解决什么

2026-11-18 实测：

- 2026-11-17（13 条）→ 6 个候选组，站点/管道那 7 条自动聚成一组；
- 2026-11-10（199 条）→ 64 个候选组，hive 的 `feat` 16 条、`fix` 15 条各自成组，不用再一条条数。

人只需要在候选组之上做两件事：合并跨仓库的同一主线、给每组写一句人话。

## 怎么跑

```bash
bun tools/2026-11-18-commit-workflow-groups/commit-workflow-groups.ts 2026-11-17
bun tools/2026-11-18-commit-workflow-groups/commit-workflow-groups.ts          # 默认昨天
```

退出码：0 = 已输出；2 = 参数或数据缺失。

## 真实示例输出（2026-11-18 首跑）

```text
2026-11-17：13 条提交 → 6 个工作流候选组

【Gaubee/gaubee.com】其它（7 条）
  📰 01915.github-daily-2026-11-16.md gaubee-skills 自动发布
  · 📊 技能 Graph 公开视图同步（1796 星标 / 129 项目 / 4164 边）
  · 🔧 2026-11-16 管道产物：两份日报 + 2 个新工具
  · …另 4 条
【jixoai/fde2e】feat(jiudian)（1 条）
  feat(jiudian): TokenPlan 全模态 + realtime 韧性 + 缓存/声音/头像收口
```

## 判读建议

- 「其它」组通常是站点自动发布与管道提交，信息量低，日报里一句话带过即可。
- 分组只是候选：同一前缀不等于同一工作流，反过来跨仓库也可能是一条主线（比如 fde2e 与它的子模块）。
- 前缀缺失的仓库（如中文 `📖 openspec：…`）会落进「其它」，别当成噪声丢掉。
