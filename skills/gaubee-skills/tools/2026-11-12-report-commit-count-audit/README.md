# report-commit-count-audit — 日报提交计数与本地日志对账

## 是什么

读每份 GitHub 日报里的「公开仓 X 条 + 私有仓 Y 条」，按当天 `github-commits/history` 的 pushes（`private` 标记）求和对比。没有该句式的旧日报跳过。

## 解决什么

日报的提交段落是手写归纳，开头那行计数最容易抄错——尤其是补跑日多仓并计。2026-11-12 首跑对账 19 份日报，抓到 4 处偏差：

- `2026-11-10`：写「公开 95 + 私有 101」，实测「公开 94 + 私有 105」（手算错一个 + 本地日志里补进了 4 条）；
- `2026-10-26 / 10-27 / 10-29`：分别差 12 / 3 / 1 条，是当时摘要数与 history 明细数的口径差。

四份都只改数字、不动日期，报告源与已发布 event 同步修正；复跑全绿。

## 怎么跑

```bash
bun tools/2026-11-12-report-commit-count-audit/report-commit-count-audit.ts --since 2026-10-20
```

退出码：0 = 全部一致（或无可对账行）；1 = 有偏差；2 = 目录缺失。纯本地只读。

## 真实示例输出（2026-11-12）

修正前：

```text
对账 19 份日报（since 2026-10-20）
偏差 4 项：
  - 2026-10-26.md：写「公开 7 + 私有 245」，实测「公开 7 + 私有 257」
  - 2026-10-27.md：写「公开 3 + 私有 105」，实测「公开 3 + 私有 102」
  - 2026-10-29.md：写「公开 0 + 私有 84」，实测「公开 0 + 私有 85」
  - 2026-11-10.md：写「公开 95 + 私有 101」，实测「公开 94 + 私有 105」
```

修正后：

```text
对账 19 份日报（since 2026-10-20）
REPORT COUNT OK：公开/私有提交数与本地日志一致（没有该句式的旧日报已跳过）
```

## 判读建议

- 与 `report-lint` 互补：它管星标总数，本工具管提交计数。
- 历史日报的偏差若是「摘要 vs 明细」口径差，修正时只改数字、日期与叙述不动（R8）。
