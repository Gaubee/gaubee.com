# vol-name-plan — 补丁卷名排期预演

## 是什么

补丁卷名固定是 `patch-<文件月份组>-<打包日 DD>.tar`。这个工具拿当前 manifest 做一次只读预演：对 staging 里每个待打包月份组，列出未来 N 天各自会叫什么卷名、会不会撞上已发布卷，以及撞了之后实际会落成什么名字。

## 解决什么

跨月回填会撞名：2026-11-07 打包 2026-10 的 4 张老图，卷名正好是 `patch-2026-10-07.tar`，与 10 月 7 日那天的补丁完全同名，打包器按 A2（同名卷不可变）拒绝继续。当天靠「跨月顺延 seq」修掉了，但排期的人仍然需要一个答案：旧月份组哪天清仓不会撞、撞了会变成 `-2` 还是 `-6`、当月组是不是只能等明天。

## 怎么跑

```bash
bun tools/2026-11-07-vol-name-plan/vol-name-plan.ts                    # 未来 14 天
bun tools/2026-11-07-vol-name-plan/vol-name-plan.ts --days 7 --json    # 机器可读
bun tools/2026-11-07-vol-name-plan/vol-name-plan.ts --staging <dir>    # 换一个 staging 根（演练/测试）
```

退出码：0 正常；1 读不到 manifest 或 staging 目录。纯本地只读，不写任何文件。

判读三种状态：

- **可用**：该日期该组没有同名已发布卷。
- **跨月撞名 → patch-…-N.tar**：卷名已被引用，但月份组不是当月，打包器会顺延 seq 出一个全新卷（A2 不变）。
- **同日同月重复 → 拒绝**：当月组当天已经打过补丁，打包器按设计 die，改日再打。

## 真实示例输出（2026-11-07，演练 staging）

正式 staging 当天已被打包清空，所以用一份模拟目录（2026-10 两张图、2026-11 一张图、2025-12 一个视频）跑预演：

```text
manifest gen 29 · 待打包月份组 3 个（未来 7 天预演）
  2025-12：1 文件 / 0.0 MB
  2026-10：2 文件 / 0.0 MB
  2026-11：1 文件 / 0.0 MB

日期         月份组   基础卷名                      状态
2026-11-07  2025-12  patch-2025-12-07.tar          可用
2026-11-07  2026-10  patch-2026-10-07.tar          跨月撞名 → patch-2026-10-07-7.tar
2026-11-07  2026-11  patch-2026-11-07.tar          同日同月重复 → 拒绝（打包器会 die）
2026-11-08  2025-12  patch-2025-12-08.tar          可用
2026-11-08  2026-10  patch-2026-10-08.tar          跨月撞名 → patch-2026-10-08-2.tar
2026-11-08  2026-11  patch-2026-11-08.tar          可用
…
最早可打包日：2026-10 → 2026-11-07（patch-2026-10-07-7.tar）
最早可打包日：2026-11 → 2026-11-08（patch-2026-11-08.tar）
```

读法：10 月组整整一个月（7 日到 31 日）都撞名，只是撞了会被顺延成新卷；11 月组今天已经打过补丁，明天起才可用。2026-11-07 真实发布的撞名卷是 `patch-2026-10-07-6.tar`（当天打包器按旧口径算出的序号），本工具据此把下一次预演成 `-7`。

## 判读建议

- 大额历史回填尽量排在「跨月撞名」的日期，代价只是卷名多一个序号，不影响发布。
- 当月组撞名没有绕法，按设计改日重跑；这也是避免同一天对同一月出两个含义不同的补丁。
