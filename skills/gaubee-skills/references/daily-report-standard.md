# 每日日报写作标准

> **适用范围**：日报、周报、月报、年报，以及一切「工作信号」类对外文案。
> **可移植性**：本文自包含，不依赖任何脚本或仓库路径，可整份复制为任意项目的 `docs/daily-report-standard.md`。
> **来源**：蒸馏自 gaubee-skills `references/writing.md`（上游：jixoai.com release-blog skill，2026-10-04）。

## 0. 一句话总纲

日报的核心是：**每条工作流一句话总结「做了什么」**。读提交记录 / 工作日志提炼，可跨仓库归组同一工作流；仓库与数字只作辅助信息，不得只罗列「N commits」。

## 1. 文体基调（默认，不问）

changelog 风格：客观、直观、通俗且准确，无晦涩词汇和比喻。按工作流分节，每节陈述「做了什么 / 为什么 / 可观察行为」，数字直接给。不写背景弧、不设悬念、不写「未来可期」式收尾，写完就停。

**平实 ≠ 稀释**：平实是降低读者的处理成本，不是降低信息量。正确形态 = 常用词汇 + 完整事实 + 结构化呈现，三者同时成立。删事实换通俗是 dumbing-down，比工程腔更早被打回。

**语域禁令**：

| 禁令 | 反例 | 正确形态 |
| --- | --- | --- |
| 成语 / 四字格装饰 | 「一眼看清」「保驾护航」 | 直陈动作与结果 |
| 口语拟态 | 把「不阻断」写成「不拦人」 | 用术语本义 |
| 散文式枚举 | 「一是…二是…三是…」 | 改用列表 |
| 破折号滥用 | 满篇「——」 | 全文预算 ≤1 个 |

## 2. 结构模板

1. **冷开一句**：分量最重的一件事，直陈。禁止暖场、禁止「本文将」、禁止标题复述。
2. **工作流小节 ×N**：每条 = 谁 + 做了什么（读提交 / 日志归纳，可跨仓库归组）+ 关键证据（提交原文短语或数字）。
   - 小节标题 = **收益动作短语**（命名读者世界的改善，如「提醒按需展开」），不是对象清单（如「XX 模块改动」打回）。
   - 正文首句 = 事实层，数字住在这里。
3. **其余信号**：收藏 / 依赖 / 杂项各一句话带过；修复与小事件默认一句话。
4. **版面占比 ≈ 决策价值**：大事件多写，小事件一句话，无事件一行带过。

**标题规范**：`报告类型：日期范围`（如 `日报：2026-10-20`、`周报：2026-10-13～10-19`，全角冒号）。全团队统一一种格式，便于归档检索。

## 3. 句级法则

| 法则 | 规则 |
| --- | --- |
| 一句一职 | 一句话只干一件事；一段只承载一个意图 |
| 长句 + 短钉 | 长句跑完推理，再用一句短陈述钉住；禁止全文口号化或无喘息长句串 |
| 数字优先于形容词 | 「强大 / 优雅 / 显著」站立的地方，放版本号 / 耗时 / 计数。形容词只能在无测量处出现一次，且是挣来的 |
| 事实强度天花板 | 一次观察 ≠ 稳定复现；性能声明不带基线就不发 |
| 归纳词 gate | 「本质上是」「核心在于」只能出现在机制讲完之后，且必须跟一个可核查的归约；否则删词留句 |
| 推测标注 | 未验证的判断用「也许 / 假设」+ 推理，或移出正文 |
| 边界结论 | 写「什么条件下值得用 / 会失效」，不写「最强 / 完胜」 |
| 比喻预算 | 全文至多一个，且只能出现在机制讲完后的定位句 |
| 专有名词预算 | 内部代号首次出现必须大白话释义；API / 包名 / 错误码是对象，照用。判据：没打开过仓库的读者能读懂每个价值句 |
| 抽象阶梯 | 标题 = 收益动作短语，正文 = 事实层。层级错位是 AI 味的第一破绽 |
| 情绪句预算 | 全文至多一句，冷句（"It's done." 级），不许感叹号堆叠 |

**高频违规示例**：

| 法则 | 反例 | 正例 |
| --- | --- | --- |
| 数字优先 | 显著提升了构建性能。 | 构建 42s → 11s（替换打包器，冷构建实测）。 |
| 抽象阶梯 | 小节标题「Vite 插件迁移」 | 小节标题「冷构建从 42s 降到 11s」 |
| 事实强度 | 修复后性能大幅提升，稳定复现。 | 3 次实测均值 210ms（基线 480ms），未做多环境验证。 |

## 4. 修订门（定稿前按序过，前关不过后关不开）

1. **R1 对账**：事实只来自源数据（提交记录、工单、脚本输出）；数字可溯源且算术自洽，口径写明（净值还是增量）。
2. **R2 追责**：每句强断言问：谁观察的、在什么上、适用范围？无源 → 删或降级为假设。
3. **R3 结构**：每段四问：比上一段多做了什么？删了会坏什么？是否两职？是否偏离开头承诺？段落 ≤240 字（剔除代码块与链接）。
4. **R4 机制**：只换名字复述变更条目 = 不合格；要说清怎么发生、何时失效。
5. **R5 查簇**：AI 痕迹按**密度**定罪（约 200 字内 ≥2 例同款才算罪，见 §5）；单处可容忍，成簇必删。
6. **R6 朗读**：出声读一遍。修复靠重组句子，不靠换连接词。

## 5. AI 痕迹清单（按簇定罪）

- 「不仅…还」「既…又」两半不加信息 → 砍成单句直陈。
- 四字滥调（极致 / 无缝 / 赋能 / 保驾护航）无测量支撑 → 删。
- 「的」链（的X的Y的Z）、主干被「在…背景下」压后 → 主语动词提前。
- 凑三项、否定式排比、无尺度「从 X 到 Y」→ 删。
- 暖场句、预告式写作、舞台式开场、元话语（「值得强调的是」）、泛化积极结尾 → 删。
- 意义膨胀：一次发版 ≠ 时代转折；无主权威（「业内普遍认为」）→ 删。
- 同义词漂移：一个概念全篇只用同一个词，不要在「配置 / 设置 / 选项」之间漂移。
- 反「表演人类」：不许加假错字、滥用 emoji、网语、借来的粗口。

## 6. 反模式（看到即打回）

1. 只写「新增了 X」，不写为什么需要 X。
2. 形容词多于数字与代码块。
3. 读完是死路（没有下一步出口）。
4. 标题 / 摘要用自造词或架构隐喻，代替读者可辨认的事实。
5. 把「通俗」做成「白痴文」（砍事实换语感）。
6. 自我标榜（「诚实的限制清单」「不是营销数字」），读者没质疑过，辩护显心虚。

## 7. 事实与口径（定稿前单独过一遍）

- 数字全部能指到源，且算术自洽。
- 第三方版本回上游 CHANGELOG 核实，不转述转手材料。
- 「新增 N」区分净值与增量。
- 术语用项目自己的词；专有名词先查项目词汇源，再判断是不是自造比喻。
- 对外发布的报告不写本机绝对路径，不夹带凭据与私有数据。

## 8. 可选：转述外部内容的条目式格式

日报里聚合外部内容（社媒动态、外链、他人动向）时，逐条成块：

> **来源 / 作者**：中文一句话点题（外文内容翻译，中文内容精炼不歪曲）＋ [原文链接] ＋ 署名

- 不全文转贴，引述 + 链接 + 署名即可。
- 媒体尽量转存到自己域下再引用（防外链失效），无媒体不硬贴。

## 9. 定稿速查清单

- [ ] 冷开一句直陈，无暖场、无「本文将」
- [ ] 每条工作流一句话总结「做了什么」，不是 N commits 罗列
- [ ] 小节标题是收益动作短语，正文首句是事实层
- [ ] 数字可溯源、口径写明（净值 / 增量）
- [ ] 形容词只在无测量处出现一次
- [ ] 破折号 ≤1、比喻 ≤1、情绪句 ≤1
- [ ] 内部代号首次出现有释义
- [ ] 无 AI 痕迹簇（200 字内 ≥2 例同款即打回）
- [ ] 段落 ≤240 字，一段一职
- [ ] 出声读过一遍；写完就停，无泛化积极结尾
