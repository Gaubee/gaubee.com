## 两处 max_tokens 预算陷阱同日实证

同一类故障出现两次：主体英译输出恒为 null，会话 LLM 命名 100% 回退到兜底。根因相同，GLM-5.3 这类思考模型的 thinking 块会吃尽输出预算，64 的 maxOutputTokens 只够推理不够正文。修复分别是英译提到 4096、会话命名提到 2048，两处 live 实证恢复。接思考模型 API 时，输出预算要按「思考 + 正文」合计估。
